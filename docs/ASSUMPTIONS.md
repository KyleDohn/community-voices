# Assumptions

These are calls we made where the brief was ambiguous. Each one says what we assumed, why, and what would
change it. Challenge any of them.

| #   | Assumption                                                                                                                                                                                                           | Why                                                                                                                                                                                                                                                                                            | Revisit if                                                                                                                                                                                                |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | The community is **discuss.pixls.us**, through a generic Discourse ingester.                                                                                                                                         | No credentials, CC BY-NC-SA license that allows a seed, about 1.2k posts/week. Reddit is closed, Discord bans AI use, and HN's terms are unclear ([research](research/data-sources.md)).                                                                                                       | The reviewers want a better-known community. Point the ingester at another Discourse forum after checking its `/tos`.                                                                                     |
| 2   | **"Without RAG" means no community data at all**: only the name, a description and the dates.                                                                                                                        | This is the literal reading of the brief. It isolates what retrieval adds.                                                                                                                                                                                                                     | The comparison looks unfair. Stretch variant C, with the whole week in context, answers "RAG vs long context".                                                                                            |
| 3   | **"The past week"** is the latest complete Monday-to-Sunday week in UTC.                                                                                                                                             | Fixed windows make runs comparable and testable. A rolling window would shift on every run.                                                                                                                                                                                                    | Reviewers want whatever is newest. Add a rolling option.                                                                                                                                                  |
| 4   | We ingest **four weeks**: one target week plus three for trends.                                                                                                                                                     | Predictions need a trend signal, and the corpus has to be bigger than one prompt for RAG to be doing real work.                                                                                                                                                                                | Volume or cost becomes a problem.                                                                                                                                                                         |
| 5   | Embeddings are **local (bge-small, 384 dimensions)**, not hosted.                                                                                                                                                    | Anthropic has no embeddings API, and the brief wants one key. The quality gap doesn't matter much for topic-level retrieval.                                                                                                                                                                   | Retrieval is visibly poor. Swap the `Embedder` for Voyage or OpenAI, which means a second key.                                                                                                            |
| 6   | **Exact vector search with no ANN index.**                                                                                                                                                                           | 3,402 chunks for four weeks of pixls. An exact scan takes milliseconds and has perfect recall.                                                                                                                                                                                                 | The corpus grows past about 100k chunks. Add HNSW.                                                                                                                                                        |
| 7   | **Opus 5.5 judges Sonnet 5.5's output**, from the same model family.                                                                                                                                                 | Keeps one key. Blinding, order-swapping and deterministic checks reduce the bias.                                                                                                                                                                                                              | Self-preference bias is a concern. Use a judge from another provider.                                                                                                                                     |
| 8   | Long-running work runs **in-process with polling**, with no job queue.                                                                                                                                               | It's a local demo. Status is stored in Postgres.                                                                                                                                                                                                                                               | Runs need to survive restarts, or several workers are needed. Use BullMQ or a pg-boss queue.                                                                                                              |
| 9   | **The API has no auth.**                                                                                                                                                                                             | It's a local single-user demo.                                                                                                                                                                                                                                                                 | It gets deployed anywhere shared.                                                                                                                                                                         |
| 10  | **English-only** posts.                                                                                                                                                                                              | pixls is mostly English, and bge-small-en is an English model.                                                                                                                                                                                                                                 | A multilingual community. Use a multilingual embedder.                                                                                                                                                    |
| 11  | We commit **raw posts, not embeddings**, as the seed, and embed on first boot.                                                                                                                                       | Keeps the repo small and shows the pipeline running. Measured first boot in Docker: 160 s to embed 3,402 chunks, with the API answering throughout.                                                                                                                                            | First boot inside Docker is too slow. Commit the embeddings too.                                                                                                                                          |
| 12  | We commit **one labeled sample A/B run**.                                                                                                                                                                            | The demo shows a full result even with no key or a bad one.                                                                                                                                                                                                                                    | Never presented as live output.                                                                                                                                                                           |
| 13  | The API image is **Debian-slim, not Alpine**.                                                                                                                                                                        | onnxruntime-node needs glibc.                                                                                                                                                                                                                                                                  | —                                                                                                                                                                                                         |
| 14  | Discourse requests are **polite**: a descriptive User-Agent, pacing well under 200 requests/min, and respect for robots.txt.                                                                                         | It's a small community forum, and we're guests.                                                                                                                                                                                                                                                | —                                                                                                                                                                                                         |
| 15  | Build time is about **8 hours, with a cut line**.                                                                                                                                                                    | TE suggests a couple of hours, but tests, CI and docs are part of the bar. Time spent is noted in `WORKFLOW.md`.                                                                                                                                                                               | —                                                                                                                                                                                                         |
| 16  | Chunk size is measured in **words (300, 40 overlap)**, not model tokens.                                                                                                                                             | No tokenizer is needed before phase 2. About 1.3 tokens per English word keeps a chunk under bge-small's 512-token limit.                                                                                                                                                                      | Retrieval shows truncated chunks, or posts are mostly code or URLs, which tokenize densely. Count with the model's tokenizer.                                                                             |
| 17  | A long topic is read **from its newest post backward**, stopping at the first 20-post batch that holds any post older than the window.                                                                               | Post IDs rise with time, so an old megathread costs one or two requests instead of dozens.                                                                                                                                                                                                     | Missing posts show up. A post moved in from another topic keeps its old date, so it can stop the walk early. Fix by stopping only when a whole batch is older, at about one extra request per long topic. |
| 18  | **`/weeks` counts posts that produced a chunk**, not every post fetched.                                                                                                                                             | Short replies are dropped at chunking and can never be retrieved, so they say nothing about what the week holds for RAG.                                                                                                                                                                       | The UI needs forum activity. Count `posts` by `created_at` week instead.                                                                                                                                  |
| 19  | **`/health` stays `ok` (200) while the embedder loads**; only `failed` is degraded. A failed load is not retried, and a failed pass leaves the status `ready`.                                                       | Everything except search works during the 2–3 minute first-boot embed, and a 503 would mark the container unhealthy for no reason. A failed pass is safe to leave: batches commit one by one and the next pass (next boot or ingestion) picks up the rest.                                     | Something depends on health meaning "search is ready", or load failures turn out to be transient. Add a readiness endpoint, or retry with backoff.                                                        |
| 20  | **Queries get bge's instruction prefix; posts don't.**                                                                                                                                                               | The model card recommends it for short query → passage retrieval. On our corpus it changed 2–5 of the top 10 per facet query, mostly for the better.                                                                                                                                           | Facet queries become long passages, or a retrieval eval shows no gain. Drop the prefix.                                                                                                                   |
| 21  | **Trend lookup takes themes as input.** Phase 3 tests it with given themes; phase 4's LLM supplies them.                                                                                                             | Theme extraction needs the LLM, which arrives in phase 4. Keeping themes an input keeps the lookup testable without a model.                                                                                                                                                                   | Themes turn out to match the facets anyway. Drop the extraction pass and trend per facet.                                                                                                                 |
| 22  | **Retrievals belong to a `retrieval_runs` row, not directly to `ab_runs`.**                                                                                                                                          | A CLI retrieval has no A/B run, but its rows should still feed the stats. `ab_runs` (phase 5) points to the retrieval run it used.                                                                                                                                                             | —                                                                                                                                                                                                         |
| 23  | **MMR vectors come from a `withVectors` search option.**                                                                                                                                                             | One query, and plain search doesn't ship 384 floats per hit. About 75 candidates × 384 floats per week is trivial.                                                                                                                                                                             | —                                                                                                                                                                                                         |
| 24  | **Retrieval history outlives chunks.** `retrievals` stores the post id and sets `chunk_id` to null when re-ingestion drops the chunk. It does not snapshot the text.                                                 | An edited post that gets shorter loses its trailing chunks; a cascade would silently erase what past runs retrieved. Snapshotting text into every row would duplicate the corpus.                                                                                                              | Stats must show exactly what a run saw after a post was edited. Store the context with the A/B run (phase 5), or snapshot chunk text.                                                                     |
| 25  | **Prompt caching only for the A/B judge.** Report runs send no cache markers.                                                                                                                                        | A report run sends each context once, plus at most one repair, so a cache write (1.25x) would rarely be read back. The four judge calls share a ~16k-token prefix. Measured: rubric and pairwise each write one entry (their schemas differ) and read it once, saving about $0.10 per A/B run. | A report run starts reusing a large context across calls, or merging the judge schemas becomes worth the clumsier prompts (about $0.07 more per run).                                                     |
| 26  | **Haiku 5.5 extracts the themes; Sonnet 5.5 writes.**                                                                                                                                                                | Naming 4–6 themes from ~40 chunks is a short, easy task; Haiku costs about 1/20 of Sonnet. The writer is the quality-sensitive step.                                                                                                                                                           | The themes come out vague or duplicate the facets. Move extraction to Sonnet (about $0.01 more per run).                                                                                                  |
| 27  | **Prediction citations may point to prior-week trend examples**; every other citation must be a target-week post from the context.                                                                                   | A prediction's evidence is the trend, and the trend's evidence is in earlier weeks. Forcing target-week-only citations would hide that evidence.                                                                                                                                               | Reviewers read "inside the target week" strictly. Show prior-week examples as uncited context instead.                                                                                                    |
| 28  | **The per-run cost cap defaults to $0.50; an A/B run has its own $1.50 cap** (`MAX_AB_RUN_COST_USD`) over all of its calls.                                                                                          | A report run costs about $0.03–0.08, so the cap only stops a runaway. The first live A/B run (a report, a no-RAG document and four Opus judge calls) cost $0.28. The Console workspace spend limit is the backstop for everything else.                                                        | Measured A/B runs cost much more or less than that.                                                                                                                                                       |
| 29  | **Spend-limit errors are matched partly by message text.** The tier cap has a typed `error_code`; the Console workspace limit is only a 400 with a fixed message.                                                    | The SDK has no typed class for it, and a 400 isn't retried anyway. Matching the message only changes the error's wording (`spend_limit_reached` vs `llm_request_failed`), never whether the run stops.                                                                                         | Anthropic adds a typed code for the workspace limit. Match on it.                                                                                                                                         |
| 30  | **An A/B run generates a fresh RAG report** instead of reusing the latest one.                                                                                                                                       | Both variants then come from the same run, which reads honestly in the demo. It costs about $0.055 more.                                                                                                                                                                                       | Runs get expensive, or reviewers want to compare against a report they already read.                                                                                                                      |
| 31  | **The judge sees the target-week posts the RAG writer read** as evidence for both documents.                                                                                                                         | Grounding can't be scored without evidence, and this lets the judge catch invented facts. It favors RAG by construction, since the evidence is RAG's own context.                                                                                                                              | The comparison looks rigged. Give the judge the whole target week instead (close to variant C).                                                                                                           |
| 32  | **The rubric is blind too**: each document is scored alone and never named as RAG or no-RAG.                                                                                                                         | Knowing the variant would anchor the score. The missing citations still give no-RAG away, which the checks report anyway.                                                                                                                                                                      | —                                                                                                                                                                                                         |
| 33  | **Retrieval stats count distinct runs per post**, not rows or chunks.                                                                                                                                                | Chunk ids go null after re-ingestion (#24), and citations use post ids. Trend lookups log more rows per run than facet picks, so rows would mostly measure trends. All 7 dev runs are one week, so ties break on total hits, then the latest retrieval.                                        | Runs span many weeks and "how often" should mean rows. Rank by rows instead.                                                                                                                              |
| 34  | **The cost list leaves out reports an A/B run made.** Their calls are already in the A/B run's cost.                                                                                                                 | Every dollar appears once and the total is the real spend recorded in the database (model tests and CLI runs aren't recorded) One gap: if an A/B run crashes unexpectedly after linking its report, the run records $0 and the report stays hidden, so the total undercounts.                  | A crash after linking shows up in practice. Then count a linked report whenever its A/B run recorded no calls.                                                                                            |
| 35  | **The map highlights a report's source posts**, not a retrieval run's rows, and sizes them by all-time distinct runs.                                                                                                | On every dev report the sources equal the run's retrieved posts (95/95, 101/101, 99/99), and the seeded sample has sources but no retrieval run. Within one run a post is retrieved once in the median case (max 3), so sizing by that would show nothing.                                     | Reports start citing a subset of what was retrieved. Highlight from `retrievals` by run instead.                                                                                                          |
| 36  | **UMAP runs in-process with umap-js**, yielding between epochs; the neighbour-graph build blocks the event loop for about 1.7 s.                                                                                     | Measured on 3,402 × 384: 4.5 s and ~500 MB RSS, deterministic with a seeded PRNG. druidjs took 7.4 s and ~1.1 GB. It runs once per corpus change, and a worker thread under `tsx` is more moving parts.                                                                                        | The corpus grows past ~20k chunks, or a 2 s stall after ingestion matters. Move the projection to a worker thread.                                                                                        |
| 37  | **The map ships title, post number and url with every point** (no excerpt), gzipped.                                                                                                                                 | Measured on 3,402 points: 948 KB of JSON, 145 KB gzipped. Long slugged urls make up much of it. A 140-char excerpt would have roughly doubled the JSON.                                                                                                                                        | Hover needs the post text. Add an on-demand post endpoint.                                                                                                                                                |
| 38  | **One footnote per paragraph**, at its end, not per sentence. The card names each post but shows no excerpt.                                                                                                         | The schema cites per section (`citations` on mood, each theme, thread and prediction), so a per-sentence number would claim a precision the model never gave. `ReportSource` carries title, url and week, not post text.                                                                       | Readers want to know which sentence a post backs, or the card needs the post text. Have the writer cite per sentence, and add the excerpt to `ReportSource` (a schema and prompt change).                 |
| 39  | **Photos come from a `/posts/media` endpoint read live from `posts`**, not from the sources snapshotted into each report. Thumbnails are the forum's own downsized copy (`src` in `cooked`), hotlinked from its CDN. | Snapshotted sources would leave every existing report, including the shipped sample, without photos. Originals can be several MB; the 690 px copy is about 50–150 KB. Linking keeps the forum the host and every image a click from its post and author (CC BY-NC-SA).                         | The forum blocks hotlinking or changes its CDN. Proxy and cache thumbnails through the API instead.                                                                                                       |
